Calculate and interpret the results

Use these steps to calculate each result. Apply the stated limits when you interpret the result.

Measurement pipeline

Calculate a matched delta

Use the same workload and one calculation rule for each pair.

  1. 01
    Run both allocators

    Run the same Redis workload with Legacy and Temeraire.

  2. 02
    Run each operation

    Run LPUSH ×5 and LRANGE 0–4 for 2,000 trials.

  3. 03
    Calculate one rate

    Calculate the harmonic mean of the two mean request rates.

  4. 04
    Compare the pair

    Calculate the Temeraire change relative to the matched Legacy run.

Supported

The test reproduced the method

The local test uses the same allocator split and a workload of the same shape, and its effects are as small as the effects in the Redis case study. On the bare-metal node, the small positive effect occurs with background release on at 16 MiB/s.

Not supported

One release setting is not a stable result

Release-off gives a negative median on the bare-metal node. The rates of 64 MiB/s and 256 MiB/s give negative medians. The paper does not state its release rate, so 16 MiB/s is a local parameter.

Not supported

The metric is a different quantity

The paper normalizes its throughput for CPU and reports requests per second per core. This test reports the unnormalized rate, joined across two operations by a harmonic mean the paper does not specify. A local percentage and a paper percentage can be close and still measure different things.

Not supported

The test did not reproduce the fleet result

The test hardware, kernel, workloads, telemetry, and allocator environment differ from the Google fleet.
